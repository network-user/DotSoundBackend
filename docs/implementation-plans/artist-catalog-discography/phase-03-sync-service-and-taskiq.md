# Phase 3 из 8 — Сервис синка каталога и Taskiq

## Общий контекст задачи (вся цепочка 1–8)

Нужно реализовать **каталог релизов артиста**: данные в таблицах (этап 1), доступ к SoundCloud (этап 2). Этот этап **склеивает** их: по **`artists.soundcloud_user_id`** тянет альбомы, импортирует треки, заполняет каталог и `TrackArtist`. Дальше этапы 4–6 добавляют API и интерфейсы поверх уже записанных данных.

Подробная матрица: [README.md](README.md).

## Роль этого этапа

**Этап 3 из 8.** **Оркестрация домена каталога:** сервис синка, Taskiq-задачи (полный синк артиста и один релиз), вызовы `import_or_get_track`, `ensure_soundcloud_ids_for_artist`, загрузка обложек в S3. Это «движок», который админка и HTTP потом только триггерят.

## Границы (анти-конфликты)

| Делает этот этап | Не делает |
|------------------|-----------|
| `artist_catalog_sync_service` (или аналог), репозитории записи в `artist_catalog_*`, Taskiq registration | Публичные роуты `/api/v1/...` для пользователей mini app (этап 4) |
| Настройка `catalog_uploader_id` в settings | Admin REST и UI редактора (этап 6) — можно временно вызывать задачу из скрипта/внутреннего вызова для проверки |
| Идемпотентность синка по плану | Mini app верстка (этап 5) |

**Prerequisites:** этапы 1–2 смержены.

**Выход для этапов 4–6:** в БД могут появиться реальные релизы после запуска задачи; публичные и админские обёртки подключаются позже.

---

## Цель

Оркестрация: по `artist_id` читать `soundcloud_user_id`, тянуть альбомы, для каждого трека вызывать `import_or_get_track`, заполнять `artist_catalog_*`, создавать `TrackArtist`, вызывать `ensure_soundcloud_ids_for_artist`. Задачи Taskiq: полный синк артиста и синк одного релиза.

## Prerequisites

Phases 1–2 смержены; в config есть стратегия `uploaded_by_id` для каталога.

## Что делать

- Новый сервис (например `artist_catalog_sync_service.py`) + репозитории.
- Taskiq tasks + регистрация брокера как принято в проекте.
- Идемпотентность и политика выравнивания позиций по плану.
- Загрузка обложек релиза в S3 по существующим паттернам.

## Критерии готовности

- Задача запускается из кода/временного вызова и заполняет таблицы для тестового артиста с валидным `soundcloud_user_id`.
