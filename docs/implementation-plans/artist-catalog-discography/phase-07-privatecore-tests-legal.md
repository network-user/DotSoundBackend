# Phase 7 из 8 — PrivateCore лимиты, тесты, legal

## Общий контекст задачи (вся цепочка 1–8)

Функциональность уже собрана (этапы 1–6). Этот этап **закрепляет качество:** лимиты синка в приватном ядре, недостающие тесты, правки legal-доков только если изменилась пользовательская/правовая картина external-source.

Подробная матрица: [README.md](README.md).

## Роль этого этапа

**Этап 7 из 8.** **PrivateCore** — константы и функции решений для лимитов синка; **Backend** — импорт этих правил в сервис синка. Расширение pytest; LEGAL при необходимости.

## Границы (анти-конфликты)

| Делает этот этап | Не делает |
|------------------|-----------|
| Новые модули в DotSoundPrivateCore по правилам репозитория | Новые пользовательские экраны (этапы 5–6 закрыты) |
| Подключение лимитов в `artist_catalog_sync_service` | Переименование публичных контрактов API без нужды |
| Тесты на синк/API | Утечку внутренних названий провайдеров в доки |

**Prerequisites:** этапы 1–6 смержены.

**Выход для этапа 8:** CI зелёный; можно делать финальный smoke и удалить handoff.

---

## Цель

Вынести лимиты синка (макс. релизов/треков, cooldown) в DotSoundPrivateCore; расширить pytest; при необходимости обновить LEGAL/docs/legal для external-source каталога.

## Что делать

- PrivateCore: модуль политик + импорт в Backend-сервис синка (без утечки имён внутренних провайдеров в публичные доки).
- Тесты: сервис синка (моки), API, при необходимости фронт не обязателен здесь.
- `LEGAL.md` / `docs/legal/*` только если меняется смысл отображения внешних треков — по правилам репозитория.

## Критерии готовности

- `make test` / `pytest` зелёный; `scripts/check_docs_sync.py` если трогали синхронизируемые доки.
