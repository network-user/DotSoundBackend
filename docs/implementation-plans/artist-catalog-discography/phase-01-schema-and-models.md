# Phase 1 из 8 — Схема БД и модели

## Общий контекст задачи (вся цепочка 1–8)

Нужно реализовать **каталог релизов артиста** в DotSound: альбомы/EP/синглы с обложками и упорядоченными треками. Автосинхронизация с **SoundCloud** использует сохранённый `**artists.soundcloud_user_id`** (numeric id пользователя в API SC) и запросы вида `GET …/users/{soundcloud_user_id}/albums`; внутренний `**artists.id` DotSound для SoundCloud не подставляется.** Треки подтягиваются через существующий `**import_or_get_track`**, связь артист–трек через `**TrackArtist`**, данные релизов — в отдельных таблицах каталога. Mini app показывает карточки релизов на профиле артиста и экран альбома с воспроизведением; админка — ручное редактирование и resync. Лимиты синка выносятся в PrivateCore на позднем этапе.

Подробная матрица ролей этапов: [README.md](README.md).

## Роль этого этапа

**Этап 1 из 8.** Заложить **персистентность**: миграция Alembic, модели SQLAlchemy для таблиц каталога и новых колонок на `artists`. Без этого следующие этапы некуда писать данные.

## Цель

Добавить миграцию Alembic: таблицы каталога релизов артиста и колонки на `artists` для привязки к SoundCloud.

## Что делать

- Таблицы `artist_catalog_releases` и `artist_catalog_release_tracks` (поля по каноническому плану: FK на `artists`, `tracks`, уникальности, `manual_lock`/`synced_at` по необходимости).
- Колонки `artists.soundcloud_user_id` (BIGINT NULL, индекс), опционально `artists.soundcloud_permalink`.
- SQLAlchemy-модели в `app/models/`, репозитории-скелет при необходимости.
- Не подключать пока синк и HTTP — только схема и модели.

## Критерии готовности

- `alembic upgrade head` проходит.
- Модели импортируются без ошибок; связи объявлены.
