# Phase 5 из 8 — Mini app: карточки альбомов и экран релиза

## Общий контекст задачи (вся цепочка 1–8)

Backend отдаёт каталог через API (этап 4). Этот этап — **пользовательский UI** в mini app: карточки релизов на профиле артиста, переход в альбом, список треков и интеграция с существующим плеером. Не меняет бизнес-логику синка и не реализует админку.

Подробная матрица: [README.md](README.md).

## Роль этого этапа

**Этап 5 из 8.** **Frontend mini app** для обычных пользователей: типы, запросы, компоненты `ArtistView` и экран релиза, навигация назад.

## Границы (анти-конфликты)


| Делает этот этап                                   | Не делает                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------ |
| `frontend/` mini app, i18n, стили по design system | Роуты в `app/api/v1/admin` (этап 6)                                      |
| Использует контракт публичного API этапа 4         | Не дублирует синк и не вызывает SoundCloud с клиента                     |
| Плеер через существующие абстракции проекта        | Не добавляет Taskiq и не правит Python-синк кроме обнаруженных багов API |


**Prerequisites:** этап 4 смержен (контракт API известен).

**Выход для этапа 6:** пользовательский UX готов; админка идёт отдельной веткой кода.

---

## Цель

В `ArtistView`: блоки-карточки релизов; переход на экран альбома со списком треков; воспроизведение через существующий playback pipeline приложения.

## Prerequisites

Phase 4 смержен (типы API известны).

## Что делать

- Типы в `frontend/src/types/api.ts`, запросы в `lib/api` или как принято.
- UI карточек релиза на профиле артиста; экран/слой релиза с ordered track list.
- Навигация назад к артисту; стиль design-system (монохром, без эмодзи по правилам проекта).

## Критерии готовности

- Ручной прогон в dev: артист с релизами отображается; треки играют как на других экранах.
